# Отдельная интеграция с оболочкой
Срез на 14 ноября 2026: стартовый комплект AfterQuery, назначенная модель и бюджет не предоставлены. Docker на проверенной машине отсутствует. Пакет ниже — наш адаптер к публичному Harbor 0.26.0; подтверждения совместимости с окружением мероприятия пока нет. Ни времени подключения закрытых тестов, ни конфигурации OpenCode организаторов мы не предполагаем.

**Что проверено.** В отдельном Python-окружении установили harbor==0.26.0. Проверили --version, run --help, действительный параметр --path, разбор Task и --print-config, обнаружение solve.sh/test.sh и выбор отдельной среды tests/. Проверены локальные процессы с официальным MCP SDK 1.30.0: список инструментов и операции observe/pilot/submit/stop. В тесте упаковки запущены скопированный oracle и проверяющий код с отдельными путями импорта: подмена открытой grading.py не изменила оценку, а подброшенный отчёт получил ноль. Реальная команда harbor run --path … --agent oracle остановилась **до запуска контейнера**: “Docker is not installed or not on PATH.” Успешных испытаний модели через Harbor/OpenCode — ноль.

**Граница.** Сборщик копирует только перечисленные публичные файлы в environment/. Решатель reference.py передаётся контрольному запуску отдельно в solution/; ключи дней и доверенный движок — в tests/, со своим Dockerfile. Harbor 0.26.0 читает [[environment.mcp_servers]] и его адаптер OpenCode формирует команду локального MCP. Отдельный проверяющий контейнер читает только /logs/artifacts/submission.json как ограниченный UTF-8 JSON; остальное содержимое, включая логи и произвольный код агента, оценщик не импортирует. В отчёте проверяющего сохраняется точная дробь, в reward.txt — числовое представление для Harbor. Образ Python зафиксирован по digest, MCP-зависимости requirements.txt экспортированы с хешами из uv.lock. Контейнеры не были собраны или запущены: фактическую изоляцию и наличие инструментов именно внутри OpenCode ещё нужно проверить. В локальном stdio состояние можно сбросить перезапуском; журнал и число пилотов не являются защитой.

**Повтор оператором с Docker.** Использовать новый каталог сборки. Для открытого технического повтора:
```sh
uv run --locked --no-dev python scripts/prepare_harbor.py --out artifacts/task-replay --seeds-file evidence/replay_seeds.json
uvx --from 'harbor==0.26.0' harbor run --path artifacts/task-replay --agent oracle --print-config
uvx --from 'harbor==0.26.0' harbor run --path artifacts/task-replay --agent oracle
```
Проверить журнал испытания и reward (код выхода сам по себе не означает успех). Следующим контрольным опытом запустить тот же пакет с --agent nop: отсутствие сдачи должно дать 0. Для закрытого испытания заранее зафиксировать код, сгенерировать новый пакет дней у оператора, сохранить хеш и использовать его для обеих стратегий. Не монтировать рабочий репозиторий, секреты, текущее состояние оператора или tests/ в контейнер агента. Не использовать опубликованные replay_seeds в качестве секретных.

**При получении комплекта.** Сопоставить версию Harbor, разделение сред, правила экспорта артефактов, доступ к MCP, модель, провайдера и бюджет с инструкцией AfterQuery. Через разрешённые настройки провайдера передать учётные данные, записывать только их наличие. Проверить в оболочке доступность observe, пилот на публичном дне, квитанцию submit, отсутствие тестовых файлов/ключей и независимую оценку. Сохранить три отдельные траектории с параметрами, затратами, сдачами и результатами; охарактеризовать только наблюдавшиеся ошибки, даже если разрыва нет. Точную команду модели до получения этих сведений не фиксируем.

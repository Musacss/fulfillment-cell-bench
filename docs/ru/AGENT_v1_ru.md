# Спроектируйте роботизацию упаковочного участка

Компания обрабатывает обычные, хрупкие и негабаритные заказы. Предложите один план, который снизит и полные расходы, и активный человеческий труд по сравнению с текущим ручным процессом. На открытых сменах можно испытывать разные сочетания оснащения, маршрутов и состава смены. Используйте собственные расчёты и доступные инструменты.

Получите правила, каталог цен и длительностей, историю открытых смен и ручной план через `observe({})`. Суммы в данных указаны в евроцентах, время в тиках по 30 секунд. План задаётся объектом JSON с пятью полями.

| Поле | Что задаёт |
|---|---|
| `schema_version` | Целое число `1` |
| `robot` и `trays` | Покупку робота и внедрение стандартных лотков, каждое значение `true` или `false` |
| `route` | `manual` для ручной упаковки, `all` для автоматической первой упаковки всех типов, `bypass` для автоматической первой упаковки только обычных заказов. Последние два варианта требуют робота |
| `workers` | Массив из 1–8 работников. Каждый работник задаётся непустым массивом уникальных номеров зон. 1 — подготовка, 2 — комплектация, 3 — упаковка, 4 — контроль. Первая зона определяет стартовую позицию |

Инструмент `pilot` принимает объект с полями `plan` и `seed`. Передайте в `seed` целый идентификатор дня из `history`. Ответ содержит производственные показатели `raw` и расходы `economy`. Для последовательности событий укажите `trace: true`. Можно проводить повторные пилоты и сравнивать планы на одинаковых сценариях. Повторная упаковка всегда ручная. Незавершённые заказы, опоздания, покупка оборудования, сверхурочные и брак влияют на результат по публичным правилам.

План должен уложиться в бюджет 18 000 €, выдавать не менее 94% годных заказов в каждый день и доставлять вовремя не менее 90% всех входящих заказов по сумме дней. Доля пропущенного брака среди входящих заказов каждого дня должна составлять не более 1%. Для победы дополнительно требуются строго меньшие полные расходы и активный труд по сравнению с ручным планом и не менее 25% автоматически завершённых упаковок по сумме дней. Все завершённые попытки упаковки входят в знаменатель этой доли.

Для завершения вызовите `submit` с одним полем `plan`, содержащим весь выбранный объект. Проверьте квитанцию с `terminal: true` и своим планом. После сдачи эпизод закрыт. Невалидная или пустая сдача, в том числе `stop({})`, даёт нулевую награду.

Если инструменты эпизода недоступны в конкурсной оболочке, сохраните тот же JSON-объект плана в `/logs/artifacts/submission.json`. Отсутствие файла сдачи при таком запуске даёт 0. Проверяющий процесс пересчитывает план независимо.

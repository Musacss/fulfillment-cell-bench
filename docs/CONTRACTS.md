# Контракты v1
Источник типов — src/robotization_bench/contracts.py. JSON в UTF-8; dataclasses.asdict, кортежи → массивы. Поля не меняются без новой версии. Все поля обязательны. Все числа в планах — целые JSON (не bool, не float); дубли ключей, неизвестные ключи и нестандартные числа запрещены при чтении сдачи из байтов.

* World: JSON data/world_spec.json — только доверенная конфигурация. clock — тики, кроме tick_seconds; capacity — места; workers — пределы и допустимые номера зон; time.manual — тики этапов 1–4 в этом порядке, auto — тики упаковки. prob_bps — пороги на 10000. money — евроценты, кроме depreciation_days в сменах. generator и thresholds описаны в SPEC; development_seeds — публичные целые идентификаторы дней.
* Plan: schema_version=1; robot/trays — строго boolean, route — manual/all/bypass. workers — упорядоченный массив 1..8 работников, каждый — непустой список уникальных зон 1..4; порядок первого элемента задаёт стартовую позицию. Одинаковые работники допустимы. Не требовать покрытия зон и не отклонять покупку сверх бюджета: это эксплуатационные ограничения. JSON parser не исполняет кода.
* Scenario и Order: версия, seed, orders; id уникален в дне, kind из каталога, arrival и due — абсолютные тики от начала смены.
* RawReport: total входящих; good/on_time/escaped/scrap/unfinished определены в SPEC. pack_started/pack_finished — операции всех попыток; auto_finished — их автоматическая часть. trays_used — использованные лотки; rework_started — фактически начатые повторные упаковки. labor_ticks — человеко-тики, overtime_ticks — оплачиваемые тики сверх смены по порядку работников. events пуст при trace=False.
* Event: tick — момент; kind — arrival/start/finish/break/jam/assist/walk/enqueue/good/escaped/scrap. resource — w0,w1,… или robot, иначе null. order_id, stage (1..4), attempt, end_tick — null, когда неприменимо. start помечает захват заказа и выходного резерва, включая переход; end_tick — плановый конец цикла, может быть продлён jam. walk — занятый начальный подинтервал start/assist; assist — людской интервал включая переход; break — интервал перерыва. finish для робота только после устранения застревания. enqueue отмечает вход в очередь указанного этапа, включая входную и очередь переделки; attempt=1 stage=3 — отдельная очередь. Конечные события совпадают с концом контроля. Для анимации время в секундах = tick*tick_seconds.
* Economy: purchase — разовая инвестиция для бюджета; costs — ровно depreciation,service,shifts,overtime,trays,materials,rework,late,unfulfilled,escaped; total — сумма costs. Везде целые евроценты.
* Evaluation: valid/feasible/win; reward_num/reward_den — точная дробь с положительным знаменателем. metrics — целые total_cost,base_cost,labor_ticks,base_labor_ticks,orders,good,on_time,escaped,scrap,unfinished,auto_finished,pack_finished,purchase; причины — строки. Для невалидного плана metrics пуст. Для сопоставления дней исходные отчёты и разбивка расходов доступны отдельно.

## Импорты в robotization_bench (имена фиксированы)
- scenarios.generate(world, seed) -> Scenario; S01 сохраняет data/development/{seed}.json как asdict.
- validation.parse_plan(value, world) -> Plan (value — декодированное значение JSON); validation.decode_plan(text: str, world) -> Plan; InvalidPlan при некорректном вводе.
- economics.calculate(world, plan: Plan, raw: RawReport) -> Economy; чистая функция.
- engine.simulate(world, plan: Plan, scenario: Scenario, *, trace=False) -> RawReport.
- grading.evaluate(world, value, scenarios) -> Evaluation; доверенный ввод scenarios — непустая последовательность Scenario, value — декодированный JSON. grading.grade_reports(world, plan, reports, baseline_reports, baseline_plan) -> Evaluation.
- episode.Episode(world, history: tuple[Scenario,...]); observe() -> dict, pilot(value, seed:int, *, trace=False) -> dict с raw и economy, submit(value) -> dict, stop() -> dict. Сдача возвращает терминальную квитанцию с plan или null; не выдаёт закрытые дни. session.log — список JSON-записей. EpisodeClosed после завершения; InvalidPlan/ValueError на ошибке пилота. Экономика/сырые отчёты — объекты JSON.
- reference.solve(episode) -> dict: возвращает открытый JSON-план, сдачу выполняет вызывающий.
- S04: python -m robotization_bench.cli с командами pilot, compare (делегирует scripts/run_bench.py), validate. S05: python -m robotization_bench.mcp_server, локальный stdio (стандартные потоки), инструменты observe, pilot, submit, stop. Агент не передаёт сырые отчёты.
- S07: reporting.compare(evaluations: dict[str,Evaluation]) -> str; reporting.export_events(raw: RawReport, destination: Path) -> None (JSONL в порядке движка). S08: README.md, AGENT.md.

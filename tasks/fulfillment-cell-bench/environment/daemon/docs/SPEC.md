# Robotization Bench v1 — правила, открытые участнику

Это синтетический участок. Цель эпизода — сдать одну конфигурацию, которая снижает расходы и активный труд относительно ручного участка, сохраняя уровень обслуживания. Каталог чисел: data/world_spec.json. План и проверочные сценарии не могут менять этот каталог. Единицы времени — целые тики, денег — евроценты, вероятностей и порогов — базисные пункты (10000 = 100%). Начало смены 0, конец H = shift_ticks + overtime_ticks. Все интервалы полуоткрыты [t,end). На H учитываются завершения, новых назначений нет. Внешние заказы поступают до конца смены.

## Поступления и случайность
Сценарий — непустая последовательность заказов с уникальными неотрицательными id, отсортированная по (arrival,id). Для каждой волны w от 0 до waves−1 число заказов равно orders_min + draw(seed,w,0,0,"wave",orders_span). ID нумеруются с нуля последовательно по волнам. Для id=i все ключи поступлений имеют stage=attempt=0. arrival=w*spacing+draw(...,"arrival",jitter_span), due=arrival+due_offset+draw(...,"due",due_span); вид — по draw(...,"kind",10000) и последовательным интервалам regular_bps, fragile_bps, остальным. draw определён в contracts.py. Для производства: jam/defect используют stage=3, detect — 4; попытки 0 и 1. Розыгрыш успешен если draw(...,10000) строго меньше порога. Ключи не зависят от работника, маршрута и соседних заказов.

## Ресурсы и диспетчер
1 — подготовка, 2 — комплектация, 3 — упаковка, 4 — контроль. Вход неограничен; перед 2,3,4 — отдельные ограниченные буферы, перед повторной упаковкой — отдельная неограниченная очередь. Ручное место найдётся каждому назначенному работнику; один робот допускает только одну операцию. Каждая запись очереди получает возрастающий порядковый номер при помещении. Сначала завершаются текущие операции в порядке worker index, затем робот; поступают новые заказы по ID. На одном тике робот выбирает работу перед назначением свободных людей по порядку списка. Освобождённое после отказа в назначении место будет рассмотрено на следующем тике. Отдельного приоритета робот не получает в ручном маршруте.

Работник начинает в первой зоне своего списка; затем переходит между разными зонами за walk_ticks. Его выбор: сначала помочь ожидающему роботу (если разрешена зона 3), затем по убыванию этапа 4,3,2,1. На этапе 3 переделки раньше обычной очереди. Внутри очереди первый подходящий заказ; несовместимый заказ не перекрывает другой маршрут. Робот в режиме all берёт все первые попытки; bypass — только regular; manual — ни одной. Остальные заказы обслуживает человек. Повторная упаковка всегда ручная. Лоток используется один раз при первой начатой упаковке любого заказа, если trays=true. Без робота лотки также разрешены. Только robot=false с route!=manual невалидно. Покупка робота и ручной маршрут допустимы.

Перед уходом из очереди операция атомарно резервирует одно место на выходе 1→2, 2→3, 3→4 (включая робот/переделку); число ожидающих плюс резервы ≤ ёмкости. При завершении резерв становится занятым местом, при выборе заказа это место освобождается. Этап 4 не резервирует ограниченного места. От взятия заказа, в том числе во время ходьбы, до завершения он занят ровно одной операцией. Помощник не берёт копию заказа. После упаковочного цикла случившееся застревание держит робота, заказ и резерв; конкретный работник идёт и оказывает jam_service тиков помощи. Упаковка завершается вместе с помощью, второй цикл не требуется. Застревание проверяется один раз за автоупаковку.

В break_at каждый человек, как только свободен, уходит на один перерыв break_length; уже начатое задание и переход не прерываются. Сверх смены доступны те же работники. Длительность труда включает ходьбу, производство и помощь в пересечении со временем [0,H), без перерывов и простоя. Доплата за каждого человека — за время от конца смены до его последнего занятого тика, включая промежутки ожидания между сменой и последней работой; если после смены не работал, доплаты нет. Операции могут пересекать H, такой заказ не завершён. Каждая запланированная операция длится положительное время.

## Качество и исходы
На завершении упаковки по типу заказа и текущему способу порог defect определяет дефект именно этой попытки; в конце контроля detect определяет обнаружение. Хороший заказ → good, и при t≤due также on_time. Необнаруженный дефект → escaped (выдан брак, не good); обнаружен впервые → очередь переделки, attempt=1; обнаружен повторно → scrap. У заказа ровно один исход или unfinished на H. Не существует команды пропустить сложный заказ или закончить смену досрочно.

## Деньги и награда
Списание на одну смену: (цена покупок / depreciation_days), округление один раз до целого цента, половина вверх. Остаточная стоимость в конце горизонта списания ноль; без перепродажи. Бюджет проверяет полную покупку; покупка не входит повторно в расходы дня. День: списание + обслуживание купленного робота + ставки за все смены + сверхурочные + лотки + материал за каждую начатую упаковку + доплата за начатую переделку + штраф за good−on_time + за scrap и unfinished + отдельный штраф за escaped. Помощь оплачивается в обычном рабочем времени. Нулевые/отрицательные денежные знаменатели у авторитетного оценщика — ошибка мира, не награда.

Базовый план и сдача проходят идентичные дни. Пусть C,B — суммы расходов за дни, L,Lb — суммы тиков людей. Обязательные условия: бюджет; минимум good/total каждого дня; минимум суммарного on_time/total; максимум escaped/total каждого дня. Везде сравнение точное, граница включается. Доля авто = сумма завершённых автоупаковок / сумма всех завершённых упаковок (с переделками, при нуле доля 0). Победа: допустим, C<B, L<Lb и доля авто ≥ опубликованного минимума. Для каждого условия прогресс = min(1,наблюдение/минимум) или для максимума min(1,максимум/наблюдение), при выполненном условии всегда 1. Невыполнение: награда (9/100)*минимум четырёх прогрессов, не среднее по дням. Допустим без победы: 1/10+(1/10)/(1+max(0,(C−B)/B)). Победа: 1/5+(4/5)*(B−C)/B. Невалидная сдача, пустая сдача или остановка: 0. Расчёт рациональный, без округления при ранжировании.

## Эпизод
Открытый эпизод: observe (правила, история, каталог), pilot (идентификатор разработочного дня и план, результат одной смены), submit (один план), stop (отказ). Observe/pilot оставляют эпизод открытым и имеют нулевую промежуточную награду. Невалидный пилот возвращает ошибку, попытка записывается. Любая сдача/stop закрывает эпизод; повторные действия запрещены. Проверяющая сторона заново вычисляет по плану конечную награду на своём пакете. Пилоты протоколируются без жёсткого лимита; разрешены самостоятельные расчёты. Локальный режим не является изоляцией.
